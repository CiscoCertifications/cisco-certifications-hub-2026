## 1. Exam Overview & Candidate Profile

The **Cisco 300-710 SNCF** exam tests a candidate's knowledge of Cisco Firepower Threat Defense (FTD) and Cisco Firepower Management Center (FMC), including policy configurations, device integrations, deployments, management, and deep troubleshooting. Passing this exam earns the **Cisco Certified Specialist - Network Security Firepower** credential and fulfills the concentration requirement for **CCNP Security**.

### Target Candidate Profile & Roles
* **Firewall Administrator / Network Security Engineer**
* **NGFW / NGIPS Operations Lead**
* **Cisco Security Solutions Integrator**
* **Prerequisites:** Familiarity with Cisco security concepts and 350-701 SCOR core material is recommended.

## 4. Scenario-Based Technical Practice Questions

### Scenario 1: Snort 3 Custom Rule Header Structure
**Question:** A security engineer needs to author a custom Snort 3 intrusion prevention rule to detect HTTP traffic originating from any external client targeting internal corporate web servers on port 8080 containing the malicious payload string `eval(base64_decode(`. What is the correct Snort 3 rule header and options structure?

* A. `alert tcp $EXTERNAL_NET any -> $HTTP_SERVERS 8080 (msg:"Malicious PHP Eval Detected"; content:"eval(base64_decode("; sid:1000001; rev:1;)`
* B. `drop udp any any -> 10.0.0.0/8 8080 (content:"eval"; action:block;)`
* C. `permit tcp $HTTP_SERVERS 8080 -> $EXTERNAL_NET any (match:"base64"; sid:1;)`
* D. `inspect ip $EXTERNAL_NET any <> $HTTP_SERVERS 8080 (string:"eval"; log:yes;)`

**Correct Answer:** **A**

**In-Depth Architectural Explanation:**
* **Why A is correct:** Standard Snort rule syntax enforces:
  1. **Action:** `alert` (or `drop`, `block`).
  2. **Protocol:** `tcp`.
  3. **Source IP and Port:** `$EXTERNAL_NET any`.
  4. **Direction:** `->`.
  5. **Destination IP and Port:** `$HTTP_SERVERS 8080`.
  6. **Rule Options:** Enclosed in parentheses containing mandatory fields: `msg` (alert description), `content` (pattern match), `sid` (Snort ID, user-defined rules start at 1000000+), and `rev` (revision).
* **Distractor Analysis:**
  * Option B specifies UDP for an HTTP web attack and uses invalid action tags.
  * Option C reverses source and destination direction and uses non-existent keywords (`permit`, `match`).
  * Option D uses invalid Snort grammar (`inspect`, `string`).

### Scenario 2: SSL/TLS Decryption Policy Configuration (Known Key vs. Resign)
**Question:** An enterprise needs to inspect inbound HTTPS traffic directed to internal public-facing e-commerce web servers hosted in the corporate DMZ. The corporate security team holds the server's private key and SSL certificate. Which SSL/TLS Policy action should be configured in Cisco FMC?

* A. Decrypt - Resign with an internal Subordinate CA certificate.
* B. Decrypt - Known Key with the server's actual public certificate and imported private key.
* C. Do Not Decrypt with Certificate Pinning enabled.
* D. Block with Reset.

**Correct Answer:** **B**

**In-Depth Architectural Explanation:**
* **Why B is correct:**
  * **Decrypt - Known Key:** Used for **inbound** SSL inspection where the organization owns the destination servers. By importing the server's legitimate private key and certificate into FMC, FTD can passively decrypt inbound HTTPS sessions without presenting a forged or modified certificate to external internet shoppers.
  * **Decrypt - Resign:** Used for **outbound** enterprise internet traffic where internal users connect to third-party websites (Google, Office 365); FTD dynamically generates a proxy certificate signed by an internal enterprise CA trusted by corporate endpoints.
* **Distractor Analysis:**
  * Option A (Decrypt - Resign) would cause untrusted certificate warnings for external customers browsing the public e-commerce portal.
  * Option C prevents any deep packet inspection by the Snort engine.
  * Option D severs user connections entirely.

### Scenario 3: FTD Advanced Packet Troubleshooting CLI
**Question:** An administrator is troubleshooting dropped packets across an FTD firewall running FTD 7.2. Traffic enters interface `outside` and should exit `inside`, but is dropped silently. Which FTD CLI utility simulates a virtual packet traversing all firewall policies (pre-filter, DAQ, Snort, NAT, routing, and LINA engine) and outputs the exact rule and engine responsible for dropping the packet?

* A. `show tech-support`
* B. `packet-tracer input outside tcp 198.51.100.1 49152 10.1.1.50 443 detailed`
* C. `tcpdump -i outside port 443`
* D. `system support view-files`

**Correct Answer:** **B**

**In-Depth Architectural Explanation:**
* **Why B is correct:** The Cisco FTD **`packet-tracer`** tool injects a simulated software packet through the entire dataplane processing chain. It outputs step-by-step verdicts from every subsystem (UN-NAT, Access List, Routing, IP Options, Inspection, Snort, VPN, Egress NAT) and identifies the exact Access Control Rule or ASP (Accelerated Security Path) drop reason if a drop occurs.
* **Distractor Analysis:**
  * Option A collects massive system state logs for Cisco TAC support cases.
  * Option C captures raw wire frames entering the physical NIC, but does not provide firewall internal policy verdicts.
  * Option D displays local disk directory structures.

### Scenario 4: Transparent vs. Routed FTD Mode
**Question:** A company integrates a Cisco FTD firewall into an existing industrial campus network where IP re-addressing or changing default gateways on legacy SCADA devices is strictly prohibited. Which FTD deployment mode must be selected?

* A. Routed Mode with OSPF
* B. Transparent Mode (Layer 2 Bridge Group / BVI)
* C. Inline Tap Mode
* D. Multiple Context Virtual Routing Mode

**Correct Answer:** **B**

**In-Depth Architectural Explanation:**
* **Why B is correct:** In **Transparent Mode**, the FTD functions as a Layer 2 bridge. Interfaces are grouped into a Bridge Virtual Interface (BVI) operating within the same IP subnet. Endpoints on either side of the firewall communicate using their existing IP configurations and default gateways without requiring IP re-addressing, while FTD continues to perform full Layer 3–7 inspection, Snort IPS, and Access Control.
* **Distractor Analysis:**
  * Option A (Routed Mode) requires the firewall to act as a Layer 3 hop, necessitating distinct subnets and gateway reconfigurations.
  * Option C (Inline Tap) inspects traffic passively without active drop capabilities.
  * Option D is invalid; multi-context is not available on all FTD models and does not eliminate Layer 3 routing requirements.

### Scenario 5: Cisco ISE Integration via pxGrid
**Question:** An administrator integrates Cisco FMC with Cisco Identity Services Engine (ISE) using the Cisco Platform Exchange Grid (pxGrid). What telemetry and contextual data does FMC gain from this integration to enrich Access Control rules?

* A. BGP EVPN route reflector updates.
* B. User Identity, User-to-IP mappings, Device Profiles, and Scalable Group Tags (SGTs).
* C. Hardware fan speeds and power supply redundancy status.
* D. Active Directory domain controller schema updates.

**Correct Answer:** **B**

**In-Depth Architectural Explanation:**
* **Why B is correct:** Cisco **pxGrid (Platform Exchange Grid)** is an open, scalable messaging fabric. When FMC connects to ISE via pxGrid, ISE dynamically streams contextual metadata—including authenticated user logins, IP-to-user mappings, device profiling classifications, and Security Group Tags (SGTs)—to FMC. This allows security engineers to construct dynamic Access Control rules based on user identity and SGTs rather than static IP addresses.
* **Distractor Analysis:**
  * Option A is a routing protocol, not an identity service.
  * Option C describes hardware environmental monitoring.
  * Option D is managed via LDAP/Active Directory domain replication.
