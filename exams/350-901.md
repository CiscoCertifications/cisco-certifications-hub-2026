## 1. Exam Overview & Candidate Profile

The **Cisco 350-901 DEVCOR** exam tests a candidate's knowledge of software development and design, including using APIs, Cisco platforms, application deployment and security, and infrastructure and automation. Passing DEVCOR earns the **Cisco Certified Specialist - DevNet Core** credential and serves as the core exam requirement for the **Cisco Certified DevNet Professional** certification.

### Target Candidate Profile & Roles
* **Senior Network Automation Engineer**
* **DevNet Software Architect**
* **Site Reliability Engineer (SRE) / NetDevOps Lead**
* **Prerequisites:** No formal prerequisites. 3–5 years designing and developing Python applications utilizing network controller APIs is recommended.

## 4. Scenario-Based Technical Practice Questions

### Scenario 1: Distributed Systems Resiliency with Circuit Breaker Pattern
**Question:** A microservice periodically synchronizes network telemetry by calling a downstream controller API. During controller maintenance, requests time out, causing thread exhaustion and cascading failures across the microservice cluster. Which software architectural design pattern should be implemented to immediately fail fast and prevent cascading outages when the controller becomes unresponsive?

* A. Observer Pattern
* B. Circuit Breaker Pattern
* C. Singleton Pattern
* D. Factory Pattern

**Correct Answer:** **B**

**In-Depth Architectural Explanation:**
* **Why B is correct:** The **Circuit Breaker Pattern** wraps remote API invocations in a state machine (Closed, Open, Half-Open). When consecutive failure thresholds are breached, the circuit trips to **Open**, immediately failing subsequent calls locally without placing network requests. After a reset timeout, it transitions to **Half-Open** to test if the backend has recovered. This prevents cascading thread pool exhaustion across microservices.
* **Distractor Analysis:**
  * Option A (Observer) is a publish-subscribe behavioral pattern.
  * Option C (Singleton) restricts object instantiation to a single instance.
  * Option D (Factory) handles object creation logic.

### Scenario 2: OAuth 2.0 Authorization Code Flow with PKCE
**Question:** A native mobile application interacts with Cisco Webex APIs on behalf of users. Because native mobile applications cannot securely protect a client secret from reverse engineering, which OAuth 2.0 extension must be implemented to prevent authorization code interception attacks?

* A. Resource Owner Password Credentials Grant
* B. Proof Key for Code Exchange (PKCE, RFC 7636)
* C. Client Credentials Grant
* D. Implicit Grant

**Correct Answer:** **B**

**In-Depth Architectural Explanation:**
* **Why B is correct:** **Proof Key for Code Exchange (PKCE)** mitigates interception of the authorization code on public clients (such as native mobile apps or single-page browser apps). The client dynamically generates a cryptographic random string (`code_verifier`) and derives a `code_challenge` (via SHA-256). During token exchange, the authorization server verifies the `code_verifier` against the challenge, proving the caller is the authentic initiator even without a pre-shared secret.
* **Distractor Analysis:**
  * Option A requires user credentials to be handed directly to the application (deprecated in OAuth 2.1).
  * Option C is strictly for server-to-server daemon authentication without user presence.
  * Option D (Implicit Grant) transmits access tokens directly in URL fragments (deprecated due to security vulnerabilities).

### Scenario 3: pyATS and Genie Parsing Framework
**Question:** A network test engineer is developing an automated testing suite using the Cisco pyATS framework. What is the role of the **Genie Parser** in this test automation pipeline?

* A. To automatically configure OSPF routing using SNMP.
* B. To parse unstructured, semi-structured Cisco CLI text output into normalized, structured Python dictionaries and lists.
* C. To provision bare-metal hypervisors across UCS blade servers.
* D. To generate synthetic traffic packets at 100 Gbps line rate.

**Correct Answer:** **B**

**In-Depth Architectural Explanation:**
* **Why B is correct:** Cisco pyATS includes **Genie**, which provides hundreds of pre-built, open-source parsers that take raw, unstructured Cisco CLI outputs (such as `show ip route` or `show interfaces`) and convert them into deeply structured, easily queryable Python data structures (nested dictionaries and lists).
* **Distractor Analysis:**
  * Options A, C, and D describe configuration management, hypervisor deployment, and hardware traffic generation (like Spirent/Ixia), none of which are the purpose of Genie parsers.

### Scenario 4: Cisco NSO (Network Services Orchestrator) Architecture
**Question:** In Cisco Network Services Orchestrator (NSO), what component is responsible for translating high-level YANG service models into low-level, vendor-specific device configuration commands across multivendor network hardware?

* A. CDB (Configuration Database)
* B. NED (Network Element Driver)
* C. FastMap Algorithm
* D. RESTCONF API engine

**Correct Answer:** **B**

**In-Depth Architectural Explanation:**
* **Why B is correct:** Cisco NSO uses **Network Element Drivers (NEDs)** to abstract physical and virtual devices. A NED translates the device-agnostic, YANG-modeled configuration stored in NSO's CDB into the native CLI commands, NETCONF XML payloads, or REST calls required by specific vendor operating systems (Cisco IOS XE, IOS XR, JunOS, Arista EOS).
* **Distractor Analysis:**
  * Option A (CDB) is the in-memory transactional database storing network state.
  * Option C (FastMap) is NSO's proprietary algorithm that automatically computes the minimal set of changes (and rollbacks) required to transition from state A to state B.
  * Option D is the northbound interface exposing NSO to external applications.

### Scenario 5: Mutual TLS (mTLS) Implementation in Microservices
**Question:** Two internal microservices communicate over HTTP/2 inside a Kubernetes cluster. To fulfill zero-trust compliance, the security team enforces Mutual TLS (mTLS). What occurs during the mTLS handshake that does not occur in standard one-way TLS?

* A. The client encrypts the payload using symmetric AES-256 before initiating the TCP connection.
* B. The server issues a `CertificateRequest` message to the client, and the client sends its own X.509 certificate in a `Certificate` message for server verification.
* C. The server requests the client's Windows Active Directory domain password.
* D. Both nodes exchange pre-shared WPA3 passphrases.

**Correct Answer:** **B**

**In-Depth Architectural Explanation:**
* **Why B is correct:** In standard one-way TLS, only the server presents a certificate to prove its identity to the client. In **Mutual TLS (mTLS)**, the server sends a `CertificateRequest` message during the handshake. The client must reply with its own X.509 client certificate and cryptographically sign the handshake (`CertificateVerify`). The server validates the client certificate against its trusted CA pool, guaranteeing bilateral authentication.
* **Distractor Analysis:**
  * Option A is technically inaccurate; symmetric keys are negotiated during the handshake, not before.
  * Option C describes password-based authentication, which is distinct from PKI certificate handshakes.
  * Option D refers to Wi-Fi wireless encryption.
