## 1. Exam Overview & Candidate Profile

The **Cisco 350-401 ENCOR** exam is the flagship professional core exam validating advanced enterprise networking concepts. Passing this single exam earns the **Cisco Certified Specialist - Enterprise Core** credential, satisfies the core requirement for **CCNP Enterprise**, and serves as the official written qualification required to sit for both the **CCIE Enterprise Infrastructure** and **CCIE Enterprise Wireless** 8-hour hands-on lab exams.

### Target Candidate Profile & Roles
* **Senior Network Engineer / Enterprise Network Architect**
* **Systems Integration Engineer**
* **Network Operations Lead**
* **Prerequisites:** No formal prerequisites. Candidates typically have 3–5 years of enterprise networking experience.

## 4. Scenario-Based Technical Practice Questions

### Scenario 1: BGP Inbound Path Manipulation
**Question:** An enterprise router R1 in AS 65000 is dual-homed to ISP-A (AS 65100) and ISP-B (AS 65200) via eBGP. Network engineering mandates that inbound traffic destined for the enterprise prefix `198.51.100.0/24` must strictly prefer the link from ISP-A. If the ISP-A link fails, traffic should failover to ISP-B. Neither ISP allows customers to send BGP MED or Community values. Which configuration applied on R1 toward ISP-B will achieve this requirement?

* A. Configure a route-map applied `in` from ISP-B that sets `local-preference 50`.
* B. Configure a route-map applied `out` toward ISP-B matching `198.51.100.0/24` that prepends AS 65000 three times.
* C. Configure a route-map applied `in` from ISP-A that sets `weight 200`.
* D. Configure a route-map applied `out` toward ISP-A matching `198.51.100.0/24` that prepends AS 65000 three times.

**Correct Answer:** **B**

**In-Depth Architectural Explanation:**
* **Why B is correct:** BGP path selection evaluates AS-Path length early in the algorithm (after Weight and Local Preference). While Local Preference and Weight influence outbound traffic leaving the local AS, influencing inbound traffic from external peers requires manipulating attributes advertised outbound. Prepending the local AS (AS 65000) three times in the outbound advertisement to ISP-B artificially lengthens the AS-Path seen by the global Internet when routing through ISP-B, causing external routers to prefer the shorter, non-prepended path via ISP-A.
* **Distractor Analysis:**
  * Option A (`local-preference 50 in`) influences outbound traffic leaving AS 65000, not inbound traffic entering from the Internet.
  * Option C (`weight 200 in`) is Cisco-proprietary and local to R1, influencing only R1's outbound forwarding.
  * Option D lengthens the AS-Path toward ISP-A, which would achieve the exact opposite outcome (making ISP-B the preferred primary path).

### Scenario 2: Cisco SD-Access Fabric Encapsulation Architecture
**Question:** In a Cisco Software-Defined Access (SD-Access) campus deployment, which two protocols are utilized in the data plane and control plane, respectively, within the campus fabric overlay?

* A. Data Plane: MPLS | Control Plane: MP-BGP
* B. Data Plane: VXLAN | Control Plane: LISP
* C. Data Plane: GRE | Control Plane: OSPFv3
* D. Data Plane: Geneve | Control Plane: IS-IS

**Correct Answer:** **B**

**In-Depth Architectural Explanation:**
* **Why B is correct:** Cisco SD-Access decouples the overlay control plane from the data plane. It implements **LISP (Locator/ID Separation Protocol)** in the control plane to map Endpoint Identifiers (EIDs) to Routing Locators (RLOCs), eliminating broadcast flooding. In the data plane, it implements **VXLAN (Virtual Extensible LAN)** with Group Policy Option (VXLAN-GPO) headers to encapsulate user Ethernet frames and preserve Scalable Group Tags (SGTs) across the fabric.
* **Distractor Analysis:**
  * Option A represents standard Service Provider MPLS/VPN architecture or Data Center BGP EVPN.
  * Option C uses legacy point-to-point GRE tunnels.
  * Option D is used in VMware NSX-T architectures, not Cisco SD-Access.

### Scenario 3: Control Plane Policing (CoPP) Implementation
**Question:** An enterprise core switch is experiencing intermittent CPU spikes caused by excessive ICMP unreachable messages and unauthorized SSH brute-force attempts. A network engineer configures Control Plane Policing (CoPP). How does Cisco IOS XE process packets targeted at the router's local IP address compared to transit packets?

* A. Local packets are handled by the CEF data plane; transit packets are routed to the control plane.
* B. Local packets punted to the CPU are subjected to the control-plane service-policy; transit packets are switched in hardware via CEF and bypass CoPP entirely.
* C. CoPP applies to all packets passing through physical interfaces before FIB lookup occurs.
* D. CoPP inspects packets only after they are rejected by ingress interface ACLs.

**Correct Answer:** **B**

**In-Depth Architectural Explanation:**
* **Why B is correct:** Control Plane Policing (CoPP) protects the router's Route Processor (CPU) from denial-of-service attacks by treating the control plane as a special logical interface (`control-plane`). Packets destined for the router's own IP addresses (management traffic like SSH/SNMP, routing protocols like OSPF/BGP, and exception traffic like TTL expired or ICMP generation) are directed to the control plane where the CoPP QoS policy rate-limits or drops unauthorized traffic. Standard transit traffic forwarded between customer interfaces is handled directly in ASICs by Cisco Express Forwarding (CEF) and never reaches the control plane.
* **Distractor Analysis:**
  * Option A reverses the forwarding architecture.
  * Option C describes data-plane port QoS policies, not CoPP.
  * Option D is incorrect; CoPP evaluates punted control traffic independently of interface ACL processing.

### Scenario 4: LISP Host Mobility Mechanics
**Question:** In a Cisco LISP environment, an endpoint (EID) moves from its home subnet on Fabric Edge Switch 1 (RLOC 1) to Fabric Edge Switch 2 (RLOC 2). What message does Edge Switch 2 transmit to the LISP Map Server to update the location of the roamed endpoint?

* A. Map-Request
* B. Map-Register
* C. Map-Reply
* D. Encapsulated Data Probe

**Correct Answer:** **B**

**In-Depth Architectural Explanation:**
* **Why B is correct:** In LISP, authoritative edge routers (Ingress/Egress Tunnel Routers - ITR/ETR) register endpoint mappings with the Map Server (MS) using **Map-Register** messages. When a host roams to Edge Switch 2, the switch detects the new host attachment via ARP/data snooping and immediately issues a Map-Register message to notify the Map Server of the new EID-to-RLOC binding.
* **Distractor Analysis:**
  * Option A (Map-Request) is used by an ITR to query the Map Resolver for an EID's current RLOC location.
  * Option C (Map-Reply) is sent by the authoritative ETR or Map Server in response to a Map-Request.
  * Option D is used for LISP RLOC reachability probing, not EID location updates.

### Scenario 5: Cisco DNA Center REST API Authentication
**Question:** An engineer writes a Python script to retrieve device health metrics from Cisco DNA Center. Before issuing GET requests to `/dna/intent/api/v1/network-device`, the script must obtain an authentication token. Which HTTP method and endpoint must be called?

* A. `GET /dna/system/api/v1/auth/token`
* B. `POST /dna/system/api/v1/auth/token`
* C. `POST /api/v1/ticket`
* D. `PUT /dna/intent/api/v1/session`

**Correct Answer:** **B**

**In-Depth Architectural Explanation:**
* **Why B is correct:** Cisco DNA Center (Catalyst Center) generates a temporary authorization token via an HTTP **POST** request to the endpoint `/dna/system/api/v1/auth/token` with HTTP Basic Authentication credentials passed in the `Authorization` header (`Basic <base64-username:password>`). The returned JSON payload contains the `Token` value, which must subsequently be included as an `X-Auth-Token` header in all intent API calls.
* **Distractor Analysis:**
  * Option A uses HTTP GET, which is rejected by the DNA Center authentication service.
  * Option C was the authentication path for legacy Cisco APIC-EM controllers.
  * Option D uses an invalid HTTP method and endpoint.
