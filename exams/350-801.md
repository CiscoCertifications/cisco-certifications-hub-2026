## 1. Exam Overview & Candidate Profile

The **Cisco 350-801 CLCOR** exam tests a candidate's knowledge of implementing core collaboration technologies, including infrastructure and design, protocols, codecs, and endpoints, Cisco IOS XE gateway and media resources, call control, QoS, and collaboration applications. Passing this exam earns the **Cisco Certified Specialist - Collaboration Core** credential, fulfills the core requirement for **CCNP Collaboration**, and acts as the written qualifier for the **CCIE Collaboration** lab.

### Target Candidate Profile & Roles
* **Voice & Video Collaboration Engineer**
* **Unified Communications (UC) Systems Architect**
* **Telecom / Telepresence Engineer**
* **Prerequisites:** No formal prerequisites. 3–5 years administering Cisco Unified Communications solutions is typical.

## 4. Scenario-Based Technical Practice Questions

### Scenario 1: SIP Early Offer vs. Delayed Offer on Cisco Unified Border Element (CUBE)
**Question:** An enterprise connects its CUCM cluster to an external ITSP SIP trunk via Cisco Unified Border Element (CUBE). The ITSP requires that all inbound SIP INVITE messages contain the Session Description Protocol (SDP) body in the initial INVITE message (Early Offer). Under the outbound dial-peer on the CUBE router, which command must be configured?

* A. `voice-class sip early-offer forced`
* B. `voice-class sip pass-through sdp`
* C. `codec g711ulaw`
* D. `media-flow across`

**Correct Answer:** **A**

**In-Depth Architectural Explanation:**
* **Why A is correct:** By default, SIP calls may use Delayed Offer where the initial INVITE does not include an SDP payload (the SDP offer is sent in the 200 OK by the callee). To force CUBE to convert a Delayed Offer call into an Early Offer call toward the service provider, the router utilizes local media resources or DSPs and requires the configuration command `voice-class sip early-offer forced` applied under the outbound dial peer.
* **Distractor Analysis:**
  * Option B (`pass-through sdp`) instructs CUBE to pass the SDP body unmodified from the ingress leg to the egress leg without transcoding; if the ingress was Delayed Offer, the egress remains Delayed Offer.
  * Option C defines allowed audio payload encoding, but does not change the SDP timing mechanism.
  * Option D is invalid syntax (the command is `media-flow-through` under `voice service voip`).

### Scenario 2: CUCM Calling Search Space and Partition Precedence
**Question:** In Cisco Unified Communications Manager (CUCM), Phone A has a Calling Search Space (CSS) configured with Partitions `[Internal_PT, PSTN_Local_PT]`. Phone A's line has a Line CSS configured with Partitions `[Emergency_PT, PSTN_LongDistance_PT]`. When a user on Phone A dials a digit string, how does CUCM evaluate the combined partitions to route the call?

* A. CUCM evaluates the Device CSS first; if no match is found, it evaluates the Line CSS.
* B. CUCM concatenates the partitions with Line CSS partitions evaluated before Device CSS partitions: `[Emergency_PT, PSTN_LongDistance_PT, Internal_PT, PSTN_Local_PT]`.
* C. CUCM merges the partitions alphabetically.
* D. CUCM ignores the Device CSS if a Line CSS is configured.

**Correct Answer:** **B**

**In-Depth Architectural Explanation:**
* **Why B is correct:** CUCM combines partitions by placing the **Line CSS partitions first**, followed immediately by the **Device CSS partitions**. The combined search order for Phone A is: `Emergency_PT -> PSTN_LongDistance_PT -> Internal_PT -> PSTN_Local_PT`. If identical route patterns exist across partitions, the pattern in the partition listed earlier in the search order is selected.
* **Distractor Analysis:**
  * Option A is reversed; CUCM always evaluates the Line CSS before the Device CSS.
  * Option C is false; evaluation order is determined strictly by the ordered CSS definition, not alphabetical sorting.
  * Option D is false; both CSSs are combined.

### Scenario 3: Dial Peer Matching Criteria in Cisco IOS XE
**Question:** An inbound SIP call arrives at a Cisco CUBE router with the following SIP INVITE header:
```
INVITE sip:5551234@10.10.10.1:5060 SIP/2.0
From: "Alice" <sip:4089998888@10.20.20.1>;tag=1c2345
To: <sip:5551234@10.10.10.1>
```
Which configuration statement on an inbound dial peer has the HIGHEST priority matching preference in Cisco IOS XE?

* A. `incoming called-number 5551234`
* B. `answer-address 4089998888`
* C. `destination-pattern 5551234`
* D. `incoming uri via URI_TAG`

**Correct Answer:** **A**

**In-Depth Architectural Explanation:**
* **Why A is correct:** Cisco IOS XE matches inbound dial peers using a strict 5-tier evaluation hierarchy:
  1. `incoming uri` (if configured and matching the specified URI parameter).
  2. **`incoming called-number`** (matches the dialed/called digits in the To: or Request-URI).
  3. `answer-address` (matches calling number in From: header).
  4. `destination-pattern` (matches calling number for inbound calls).
  5. Default dial-peer 0 (if no match is found).
  Among the direct digit matching commands, `incoming called-number` takes precedence over `answer-address` and `destination-pattern`.
* **Distractor Analysis:**
  * Option B (`answer-address`) is third in priority.
  * Option C (`destination-pattern`) is fourth in priority for inbound calls.
  * Option D is only evaluated if `incoming uri` matches; here `incoming called-number` directly matches the called DN.

### Scenario 4: DiffServ Voice Packet QoS Marking
**Question:** According to Cisco and IETF RFC 4594 QoS guidelines, what DiffServ Code Point (DSCP) and Class of Service (CoS) values should be assigned to voice media (RTP audio stream) and voice signaling (SIP traffic), respectively?

* A. Voice Media: DSCP EF (46) / CoS 5 | Voice Signaling: DSCP CS3 (24) / CoS 3
* B. Voice Media: DSCP AF41 (34) / CoS 4 | Voice Signaling: DSCP BE (0) / CoS 0
* C. Voice Media: DSCP CS5 (40) / CoS 5 | Voice Signaling: DSCP EF (46) / CoS 5
* D. Voice Media: DSCP AF11 (10) / CoS 1 | Voice Signaling: DSCP AF21 (18) / CoS 2

**Correct Answer:** **A**

**In-Depth Architectural Explanation:**
* **Why A is correct:**
  * **Voice Media (RTP):** Classified as Expedited Forwarding (**DSCP EF**, decimal 46, binary `101110`) and Layer 2 **CoS 5**. This ensures voice frames enter the switch and router Priority Queue (PQ / LLQ).
  * **Voice Signaling (SIP/H.323):** Classified as Class Selector 3 (**DSCP CS3**, decimal 24) or AF31 (decimal 26), and Layer 2 **CoS 3**.
* **Distractor Analysis:**
  * Option B marks voice media as interactive video (AF41) and drops signaling to best effort.
  * Option C reverses signaling and media priorities.
  * Option D provides insufficient prioritization, causing severe audio jitter and packet loss.

### Scenario 5: Cisco Mobile and Remote Access (MRA) with Expressway
**Question:** A remote employee uses Cisco Jabber from home over the Internet to access corporate voice and voicemail services without establishing a traditional VPN. How does the Cisco Expressway solution facilitate this connection?

* A. Expressway-C sits in the DMZ and terminates TLS from the client; Expressway-E sits in the corporate LAN.
* B. Expressway-E resides in the DMZ, terminates public TLS/HTTPS connections from Jabber, and proxies them over an internal secure traversal zone to Expressway-C inside the corporate LAN.
* C. The remote client connects directly to CUCM over UDP port 5060.
* D. Expressway-E acts as a RADIUS server to authenticate the endpoint via 802.1X.

**Correct Answer:** **B**

**In-Depth Architectural Explanation:**
* **Why B is correct:** In Cisco Mobile and Remote Access (MRA):
  * **Expressway-Edge (Expressway-E)** resides in the perimeter network (DMZ). It terminates public TLS connections from external clients (Cisco Jabber or Webex) and handles authentication and STUN/TURN media relay.
  * **Expressway-Core (Expressway-C)** resides on the internal corporate network. Expressway-C initiates an outbound unified traversal connection to Expressway-E (preventing inbound firewall holes). Expressway-C proxies SIP, TFTP, and HTTP requests to CUCM and Cisco Unity Connection.
* **Distractor Analysis:**
  * Option A reverses the roles of Expressway-C and Expressway-E.
  * Option C exposes internal telephony infrastructure directly to the public internet, creating critical security vulnerabilities.
  * Option D describes an authentication server, which Expressway is not.
